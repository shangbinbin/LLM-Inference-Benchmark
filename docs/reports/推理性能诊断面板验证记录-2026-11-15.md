# 压测推理性能面板扩展验证

原有面板主要覆盖吞吐、延迟和运行/排队，缺少执行阶段、工作负载长度、缓存与调度压力，以及实例差异。现在为 vLLM 和 SGLang 各提供 21 个性能/诊断面板；PD 配置为 SGLang 额外生成 4 个队列/传输面板，另有 3 个可选 HTTP 响应面板。默认 NVIDIA 总览包含 74 个指标/日志面板，海光包含 75 个；所有非分区面板均有简短指标说明。

新增“推理实例”筛选，并保留实例输出吞吐、运行/排队和 TTFT P99 对比；主机、GPU、日志筛选保持独立。纠正 vLLM 请求级 TPOT 与旧版输出间隔命名的混用；SGLang 周期重调度 Gauge 不求 rate，不解释成当前队列长度。均值按样本加权、缓存比例按 Token 加权，分位数合并桶后计算，不平均实例分位数。无流量/缺失直方图不生成假零；HTTP 错误比例仅在已观测到生成接口响应时补缺失错误类别的零。

验证结果：

- `python3 -m unittest discover -s tests`：160 项测试通过。
- `python3 tests/verify_inference_promql.py`：Prometheus v3.5.0 promtool 解析 166 条不同查询并通过 24 个数值/语义断言。包含不同实例权重、其他任务/job 隔离、KV 新旧名回退、TPOT 与 ITL 分离、阶段隔离、Gauge 波动、零流量/指标缺失，以及 HTTP 分类和错误比例。脚本已提交，可用本机 promtool 或已有镜像复现；Docker 模式 `--pull=never --network none`。
- 实际 Docker 观测栈以 `--no-benchmark` 启动，Grafana 自动加载扩展后的 Dashboard 和实例筛选；74 个非分区面板均有描述，143 个 Prometheus 查询执行成功。已有 SGLang 运行请求 Gauge 仍能查询；模拟服务未暴露的 HTTP 计数器未被显示为零错误率。
- 两份 YAML 快照与生成器一致，普通/PD 拓扑的面板无布局重叠，`git diff --check` 通过。

指标依据 vLLM v0.11.0、SGLang v0.5.5 的公开实现和官方说明核对。此次实际容器验证使用模拟服务，没有部署真实 vLLM/SGLang 模型；真实服务版本、可选直方图、PD 指标与设备 profiling 仍需按现场 `/metrics` 核对。说明、来源、启用条件和瓶颈排查表见[压测性能诊断](../推理性能诊断与瓶颈排查.md)。更新源码后用原配置 down，再 up --no-benchmark 重新生成面板，无需重建镜像。
