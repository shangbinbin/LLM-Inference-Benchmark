# nerdctl 接入验证记录（2026-11-12）

验证对象为正式启动器、CLI、顺序压测、SLO trial 和离线诊断的 nerdctl 路径；Docker 路径保留并执行回归测试。

## 环境与边界

使用独立测试容器内的真实 nerdctl 2.1.3、containerd 2.1.3、CNI 1.7.1，独立 namespace 为 llm-bench-validation。从外层 Docker 已缓存的七个 amd64 镜像生成归档，使用 nerdctl load 导入；没有拉取或重建业务镜像。nerdctl full 发行包 SHA256 为 `e4750ba025c1a9b3d365285f800e683287ee782f0a878bc8c395f28d7bc194ba`。

当前云环境不允许 runc 创建子 cgroup，原生 runc 试运行在创建 task 时返回 `mkdir /sys/fs/cgroup/llm-bench-validation: permission denied`。因此本次集成测试使用 runsc release-20260413.0 的 systrap/ignore-cgroups OCI 后端，仍由真实 containerd 管理任务、nerdctl 管理镜像/网络/容器。为该沙箱测试的 CNI 网络补充 loopback 插件，使 Loki 内部 127.0.0.1 gRPC 通信可用；首次缺少 loopback 的日志查询失败，补齐后重新执行验证通过。这些调整仅用于独立测试环境，未写入生产启动器，也未修改节点原有 Docker/containerd 配置。

这不是生产 runc/cgroup、NVIDIA 或海光硬件验证。GPU 数据来自 CPU fixture，推理服务为模拟接口；真实节点需按 [nerdctl 指南](../nerdctl.md)核对驱动、nvidia-container-cli、CNI、cgroup 和设备权限。没有借助 Docker 兼容伪造器替代 nerdctl 的检查结果。

## 验证结果

| 检查 | 结果 |
| --- | --- |
| Python 单元/回归测试 | 110 项通过，覆盖 Docker 与 nerdctl 的参数差异、namespace、清理保护、CLI profile 和诊断 |
| 离线镜像 | 七个缓存镜像可从 Docker 归档导入 containerd；按配置平台 inspect 成功 |
| namespace 反例 | 切到空 namespace 后列出 7 个缺失镜像；未创建项目 state、容器或网络 |
| 完整 up | fixture、node_exporter、Loki、logrotate、Alloy、Prometheus、Grafana 启动，全部采集目标 UP |
| 单次 AISBench | 8 次正式请求全部成功，0 失败；验证 create → start -a → inspect/ExitCode |
| 顺序压测 | JSONL 2 请求、ShareGPT 3 请求、random tokenid 4 请求均通过；验证数据挂载、run --rm 及日志报告 |
| SLO trial | 并发范围 1..1、1 次测量、8 请求通过，正确清理临时 probe/client；此结果不代表容量上限 |
| 指标与日志 | 模拟 GPU canonical 标签、node 指标、Loki 任务日志、预置 Dashboard 均通过 verify_simulation |
| Grafana 浏览器 | 页面、Prometheus/Loki 数据源查询无错误；Dashboard 中可显示 Logs Volume 及请求日志 |
| 轮转与重启 | 强制轮转日志、重启 Alloy/Prometheus/Loki/Grafana 后，旧日志和新日志均可查询，GPU 指标恢复 |
| 诊断 | nerdctl logs/inspect 按项目标签收集，诊断包生成成功；首次包 23 个文件且 collection_notes 为空 |
| down | 项目容器和网络删除、状态移除，压测结果/持久化数据保留；同 namespace 的 foreign 项目容器保留 |

为执行轮转验收，测试文件 server.log 临时补充了宿主测试用户的写权限；未改变生产日志权限。测试创建的 foreign 资源用于验证清理范围，验证后由测试脚本单独删除；namespace 内没有执行全局 prune。

测试期间 runsc/nerdctl 偶有退出后转发信号及已退出容器 NetNS 检查警告；退出码、报告和持续运行组件状态均另行核对，不把警告本身当成成功证据。

## 可在目标机复验的命令

```bash
./bin/llm-bench images check --config generated/site/nerdctl-smoke.json
./bin/llm-bench up --config generated/site/nerdctl-smoke.json
python3 scripts/verify_simulation.py --config generated/site/nerdctl-smoke.json
./bin/llm-bench bench suite --config generated/site/nerdctl-smoke.json --cases configs/suites/mixed-datasets.json
./bin/llm-bench logs collect --config generated/site/nerdctl-smoke.json
./bin/llm-bench down --config generated/site/nerdctl-smoke.json
```

先按指南复制冒烟模板、配置相同 namespace 并导入全部镜像。需要检查轮转/重启时，确保测试日志文件对当前执行用户可写，再给 verify_simulation.py 添加 `--exercise-restart`；该工具只允许操作 simulation 配置。
