# node-exporter 主机面板验证

任务总览的 NVIDIA 与海光版本均新增 15 个主机资源面板，包含采集健康、CPU 使用率/I/O 等待、负载、内存/Swap、文件系统、磁盘 I/O 和网络吞吐/错误/丢包。“主机采集目标”依赖任务；“主机网卡”依赖任务和主机，支持单选、多选及 All，保留同机场景的 lo、Docker 网桥和 veth 流量。两份 YAML 快照已同步，生成命令直接输出 YAML。

验证结果：

- 全部 157 项 Python 测试通过，包括筛选依赖、指标范围/单位/容量保护、容器与宿主机说明、面板布局和 YAML 快照生成检查。
- 使用 Prometheus v3.5.0 的真实 promtool 执行 52 个查询断言：两厂商 50 个面板查询，加上采集失败目标保留、All 网卡包含回环/虚拟网卡两个场景。输入包含 282 条指标序列、其他任务/主机、虚拟文件系统、零容量挂载点和虚拟块设备。CPU、内存、磁盘/网络速率数值及筛选结果均通过。
- 实际启动 Linux x86_64 Docker 观测栈（`--no-benchmark`），Grafana 自动加载 15 个主机面板及两个筛选变量，全部 25 个主机查询执行成功；采集健康、CPU、内存和网络指标均有数据。使用容器模式，文件系统的虚拟挂载点过滤后允许无数据；未将它当成宿主机全量文件系统验证。
- `git diff --check` 通过。此次只修改 Dashboard、快照、文档及测试，无需重建镜像。已有栈更新源码后须先 down，再 up --no-benchmark，重新生成并加载面板。

真实单机共节点部署应保持 `host_metrics: host` 并设置容器可达的 `node_exporter_target`。指标反映节点整体资源，GPU external 多节点配置不会自动增加其他节点的 node-exporter 采集；详细口径见[任务观测说明](../task-observability.md#主机资源的筛选与采集口径)。
